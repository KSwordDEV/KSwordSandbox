# 公开样本清单可读性与一致性审查

审查日期：2026-10-15  
审查对象：[`docs/sample-calibration.md`](sample-calibration.md)  
审查范围：样本数量、身份字段、公开报告链接可达性、行为结论与噪声边界、失败状态表达、报告/UI 的可读性。未下载、解压、执行或保存任何样本二进制。

## 结论

清单已经满足“至少 10 个样本结果”的数量要求，共列出 14 个条目，覆盖 Remcos、Lumma、Agent Tesla、RedLine、FormBook/XLoader、XWorm、njRAT/NJRat、SmokeLoader 和恶意 PDF。14 个 SHA-256 都是 64 位十六进制字符串，且 URL 中的 SHA-256 与表格字段逐条一致。

在 2026-10-15 的 HTML 可达性检查中，14/14 个 ANY.RUN 报告 URL 的 `HEAD` 和 `GET` 均返回 HTTP 200；GET 返回的页面标题均包含 `Malicious activity`，页面 HTML 中也能找到对应 SHA-256。这个结果只证明公开报告页面可访问和身份键可核对，不能证明 KswordSandbox 已经在本机成功运行过这些样本，也不能把第三方 verdict 当成本机动态结论。

当前清单适合作为“公开报告校准输入”，还不适合作为“本机分析成功率报告”。表格把已观察行为、期望高信号、可能行为和噪声放在同一行，分析状态和证据强度没有独立字段；这会让 UI 把条件性描述误显示为已发生事件。

## 逐行审查

下表中的“需补证”表示清单文字不足以区分“报告中已观察到”与“只是该家族的常见行为”。它不表示样本是安全的，也不表示公开报告本身错误。

| 行 | 目前可读的主结论 | 噪声边界是否清楚 | 需补证或修订 |
|---:|---|---|---|
| 1 | Remcos 外连、TLS/JA3、动态 DNS/C2 | 清楚列出 mDNS、广播和 Skype 噪声 | 把 `外连`、`C2 域名`、`TLS JA3` 映射到统一的“网络/C2”类别 |
| 2 | Remcos TLS/C2 与 ngrok DNS | 清楚列出白名单 Skype 和系统 DNS 重复行 | 与行 1 使用同一套事件名称，避免 `网络木马`、`网络告警` 混用 |
| 3 | Lumma、AutoIt/NSIS loader | 解包、临时文件和沙箱启动进程已列为噪声 | “浏览器/钱包/凭据读取（若采集到）”是条件语句，不能出现在“已观察结论”中；应标为“待复测/期望行为” |
| 4 | Lumma C2/check-in | 代理重复 DNS 和浏览器联网已标噪声 | `check-in` 建议显示中文“上线/回连”，原英文放复制字段 |
| 5 | Agent Tesla、键盘和信息窃取 | CLR/Mono 初始化已标噪声 | 需显示键盘/凭据事件的来源进程和证据 ID；仅家族说明不能单独证明窃取成功 |
| 6 | 解压后 AgentTesla、FTP 外传、主机/CPU 出站 | WinRAR、日志和 IP 查询边界清楚 | `ip-api.com` 查询与信息外传应拆成两个事件，避免一个“外部 IP”标签吞并真实外传 |
| 7 | Agent Tesla 凭据窃取和 SMTP 外传 | LLMNR/mDNS、ipify 已列为噪声 | 明确 SMTP 目标、端口和来源进程；普通 IP 查询不应继承 SMTP 的高风险颜色 |
| 8 | RedLine/MetaStealer TCP C2 | Bing、SearchApp 和启动网络活动已列噪声 | 统一 `RedLine`/`Redline` 的显示名称，并把 IDS 重复告警合并计数 |
| 9 | FormBook/XLoader 静态标签 | .NET/NetReactor 初始化和临时文件已列噪声 | 当前“已观察结论”主要是 PE/.NET 和标签，浏览器/凭据/键盘/C2 在本行只出现在期望项；应标为“静态/动态待补证” |
| 10 | XWorm 落地、Run、Startup、Task Scheduler | GUID、语言、安装日期和 IE 设置已降级为侦察 | “环境检查”应单独放环境侦察类别，不能和持久化共用一个行为标签 |
| 11 | RAR 解包后落地并加载 njRAT | WinRAR、手工启动和机器信息已列噪声 | 家族加载证据与“持久化或 C2（若出现）”应分开；后者是条件项，不能作为本行已发生结果 |
| 12 | NJRat YARA、NETSH 防火墙变更、可执行文件落地 | 系统服务和沙箱启动器边界清楚 | 统一 `NJRAT`、`NJRat`、`njRAT` 为一个规范家族名，保留原始文件名 |

## 一致性问题

1. **家族名不统一。** 同一组样本同时出现 `Agent Tesla`、`AgentTesla`、`NJRAT`、`NJRat`、`njRAT`、`RedLine` 和 `Redline.exe`。应存储 `familyKey`（例如 `njrat`）和 `displayName`（例如 `njRAT`），文件名保留为原始字段。
2. **事件动词不统一。** “外连、外传、check-in、连接目标、落地、加载、读取”混在行为列中。建议固定为“执行、文件、网络/C2、凭据、持久化、环境侦察、采集质量”七类，并在每个事件上保留 `observed`、`expected`、`noise` 三态之一。
3. **观察与期望混列。** “若采集到”“若出现”“需要同时存在”表示条件或验收规则，不是报告已观察事件。它们应离开“已观察到的行为结论”列，进入“待验证行为”或 fixture 的 `expectedSignals`。
4. **证据强度缺失。** 家族标签、YARA/信誉、动态事件和外传成功的证据强度不同，当前均以普通文本呈现。至少增加 `evidenceType`（动态/静态/信誉/规则/环境）和 `confidence`（高/中/低）。
5. **分析状态缺失。** 清单没有逐样本的运行结果。UI 需要把“动态成功、动态部分成功、未执行或不支持、采集失败”作为独立筛选值；空事件表只能在状态旁显示，不能被解释为安全。

## 失败与“没有观察到行为”的边界

这些状态应在样本卡片和事件表中直接显示，并保留原因：

| 状态 | 判定条件 | 用户看到的文案 |
|---|---|---|
| 未执行或不支持 | `unsupported file type`、`rejected`、`error`，或没有样本进程 | “未执行或格式不受支持；仅有静态/信誉证据” |
| 动态部分成功 | 有文件/进程等本地事件，但网络关闭、代理失败或环境限制 | “动态部分成功；未观察到网络行为（环境限制）” |
| 证据不足 | 只有手工启动、父进程初始化、超时或未触发样本子进程 | “证据不足，需要复测” |
| 只有环境/规则证据 | 仅有家族文本、YARA、VT、`agent.start`、R0 health 或报告元数据 | “未采集到样本归因证据” |
| 采集失败 | 设备不可用、队列丢弃、collector/staging 异常 | “采集失败；请查看采集质量” |

`agent.start`、手工点击、WinRAR/浏览器/Office/Acrobat 启动、`svchost.exe` 的 mDNS/LLMNR、代理探活、R0/驱动健康、队列和报告页面元数据都是时间线事实或采集质量信息，不应单独计为样本恶意事件。读取机器名、语言、GUID、DMI、安装日期和环境变量时，只显示“环境侦察”；出现外传、凭据读取或持久化证据后才升级主结论。

## 排版与 UI 友好性

当前 Markdown 作为审查源文件可读，但直接转成 UI 会产生横向滚动和信息层级混乱：七列中有五列包含长句、哈希和 URL；“已观察”“应计高信号”“预期噪声”同时出现，用户需要读完整段落才能判断结果；英文技术词和中文说明混排，也容易把规则标签误当动态行为。

建议将首页改成“筛选栏 + 紧凑表格 + 宽详情抽屉”：

- 筛选至少包含家族、行为类别、信号级别、分析状态和来源；显示当前筛选结果数与“未采集到样本归因证据”的空结果文案。
- 表格行只放样本名、规范家族、状态、风险级别、代表性高信号数、噪声数、来源按钮；SHA-256 默认截断并提供复制。
- 详情抽屉使用足够宽的横向区域，先展示 3--8 条代表性证据；长命令、脚本、stdout/stderr 和原始事件折叠，来源链接显示“打开公开报告”和检查日期。
- 用色块/标签区分“样本归因”“环境噪声”“采集质量”，同时保留文字和图标，不能只靠颜色；删除 `agent.start`、内部 prompt、collector 调试串和无意义的重复提示。
- 中文作为主标签，例如“上线/回连”“外传”“环境侦察”“采集失败”；`C2`、`JA3`、`YARA`、`NETSH` 等技术 token 可保留为英文复制字段并提供中文解释。

完成上述改动后，审查员应能在单行内回答：样本是什么、动态是否成功、哪几条是高信号、哪些只是噪声、为什么失败、如何打开原始证据。
