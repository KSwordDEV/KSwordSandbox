# 破坏性样本行为矩阵去重（2026-10-26）

本页把[21 个候选](destructive-sample-catalog-2026-10-26.md)和已取得的密封归档按**可独立检验的破坏机制**收敛。一个机制先保留一个代表；同一份样本若实际覆盖两个机制，不为第二个机制重复运行。家族名、归档文件名和公开报告都不是本机动态证据。真实代码只能在无网卡、零宿主共享的可丢弃 VM 克隆内执行，实体机严禁执行。

| XData 新一轮已有 24 个不同原文件的基线哈希变化及原生高危命中，但完整来宾输出仍因 GuestOps 失联。 | **已证实通用文件转换检出，采集仍不完整**：高危结论来自回收日志，不把缺失的后续行为或原始磁盘状态视为阴性。 | 将快速回收纳入正式发布运行路径；增加停机后、回滚前的只读 VMDK 取证以覆盖 GuestOps 失联。 |
| Prestige 在隔离 VM 尝试但 VIX/GuestOps 失败，样本未启动。 | **实验运行失败**：`partial` 报告保留作部署链诊断，不能用于判断恢复抑制有无。 | 先定位来宾调用失败，再检查卷影/备份的命令与实际前后状态。 |

## 合并规则与恢复重复样本的条件

1. 只看**受控对象上的机制**：文件哈希/存在性、磁盘扇区或分区结构、VSS 状态、PE 结构，而不是家族名称、勒索字样或公开标签。同一个样本可以覆盖多列，覆盖必须由本机直接证据证明。
2. 每个代表先跑一份。若结果是“样本未启动”“需要另一个阶段”“对应采集通道缺失”或“来宾防护拦截”，这不是该机制的真阴性；可换同组备用样本，但必须记录替换原因，不能把两者均计为独立机制覆盖。
3. 同族 A/B、旧/新构建仅在修复规则后做**回归**，或验证已明确提出的时间线差异；不会计入新增破坏机制。DynoWiper A/B、CaddyWiper 两变体、HermeticWiper 两构建、Azov 旧/新尤其如此。
4. 断网单 VM 不能评价横向传播、C2 或外部共享传播。WannaCry、NotPetya 的传播标签不进入当前矩阵分母；必要时另设计可封闭的多机网络实验，而不是在本克隆上改开网卡。
5. 当前用户态包缺 R0，规则集中有文件删除、文件写入和勒索扩展名/恢复抑制信号，但没有足以独立证明原始扇区、MBR 或分区覆写的专用高置信结论。对这两列应以 VM 层只读磁盘比对和采集缺口同时报告；不能用“高风险”封面反推所有预期破坏动作都被采到。

## 状态纠偏与公开分析边界

早期[候选清单](destructive-sample-catalog-2026-10-26.md)与[归档清单](additional-sealed-samples-2026-10-26.md)保留了当时“未取得/未核内文件”的时间点，不能直接当作当前状态。随后宿主仅作**数据解码与哈希**，确认 Jigsaw、RedBoot、Cerber、Thanos 内文件 SHA-256；DynoWiper A/B、CaddyWiper 与 Prestige 的密封字节也已取得，其中 DynoWiper、CaddyWiper 仅有部分取证，Prestige 的隔离 VM 尝试因 VIX/GuestOps 失败而仅有部分报告，不能评价恢复抑制。Mamba 的 `131.exe` 经 7-Zip 和 Python `zipfile` 双流式核验，并在来宾确认 NotPetya DLL 的 `027cc450...`。宿主从未执行恶意样本。Jigsaw 与 Cerber 的早期实验室中转路径在来宾读取时被拦截；Cerber 后续产品直传完成且可评价本轮终态。一次性来宾准备轮次的 `MpCmdRun -ResetPlatform` 退出码为 0，重启后 `Get-MpPreference` 列出 `C:\KSwordSandbox\incoming` 排除路径，但同轮 `engineHealthy=false`；这是来宾防护健康异常，不再作为 Cerber 产品直传不可行的结论。RedBoot 第二次尝试无样本启动证据，第三次有启动证明但因重置丢失事件及 Agent 退出记录；两者均不能证明 MBR/擦除行为。Thanos、WannaCry 的初版报告漏判高危；同一通用规则在各自原始证据上重建后，分别凭 36、15 个不同文件的转换证据各给出 1 条高危，勒索信只作伴随观察。Locky、TeslaCrypt 的完整作业没有诱饵变化，Satana 虽完整取证但早退；XData 最新轮次由通用规则凭 24 个不同文件的前后内容变化给出 1 条高危，但 GuestOps 失联使报告仍为部分取证；它与 Thanos、WannaCry 属同一文件转换机制，不增加独立机制数。R0 缺失及 RedBoot 重启后的证据回收则需分别作为采集/环境限制记录。每次实测的最终状态以该 job 的原始事件、任务报告与回滚记录为准。
