# VMware 动态报告审查与修复记录

2026-10-16 对十份旧的真实样本报告和十份受控校准报告进行了逐份复核。审查使用 `events.json` 原始事件、`report.json` 采样视图、运行元数据和公开行为资料交叉核对。

## 结论

- 旧报告中的“无高风险行为”不能解释为样本安全。Agent Tesla、AZORult、KPOT、PsiXBot、Trickbot 的公开能力与本机短时运行结果之间存在明显覆盖缺口。
- 原始事件约有九成未进入 HTML，主要原因是诊断配额吞掉了无归因的 TCP、任务和持久化边沿；这属于报告采样缺陷，不是行为不存在。
- 真实样本多数在非交互 Session 0 中短时退出；没有 R0/WFP、ETW live、PCAP、内存和可靠的掉落文件采集时，只能给出“运行期不可判定”或“已观察执行但未命中规则”。
- 受控样本中，进程/文件/TCP 的短边沿会在快照间隔内消失；任务 CSV 受中文表头影响；进程树曾把环境进程错误挂到样本根；普通 `file.*` 行曾被错误渲染成掉落文件。

## 已落地修复

- 采样器新增有界动态证据桶，优先保留 TCP、文件、注册表、启动项、计划任务和服务边沿；显式 finding 证据先于诊断配额；退出码、失败原因、任务动作和值字段固定保留。
- 报告 verdict 区分执行阻断、非零退出、仅生命周期、无运行证据和真正的规则命中；静态/家族线索不再代替运行期结论。
- Guest Agent 在进程退出前补一次边沿采集；文件探针覆盖 TEMP 根的沙箱文件并写入真实阶段；TCP 事件携带协议、端点和归因缺口；PID 0 不再当作有效归因。
- 进程树只在存在根树元数据时挂载样本根；`schtasks` 解析支持中文表头；fallback/mock Guest Agent 先分离启动并立即写 PID，使 live sync 与样本运行重叠。
- PostProcess 与在线管线统一使用 `artifact-index.json`；普通文件观察不再伪造可下载掉落文件。

## 证据边界

没有把未知归因动态行升级为恶意行为，也没有把未启用的 R0/ETW/PCAP/内存/掉落文件采集写成已采集。短于轮询间隔的网络、文件、互斥体和线程行为仍需要事件驱动源（R0/WFP/ETW/FileSystemWatcher）才能达到产品级覆盖。

报告输出仍位于宿主机运行目录，例如：

`D:\Temp\KSwordSandbox\jobs\<jobId>\report.zh.html`

完整原始证据：

`D:\Temp\KSwordSandbox\jobs\<jobId>\guest\<jobId>\events.json`
